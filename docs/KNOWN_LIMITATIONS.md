# ROADGUARD AI — Known Limitations

This register lists what the prototype does **not** do, and what a reader must not infer from it.
Anything marked BLOCKED was not verified in this environment.

## 1. AI and computer vision

| Limitation | Detail |
| --- | --- |
| **Default detector is not a trained model** | `DETECTOR_BACKEND=synthetic_scene` runs real OpenCV colour-marker segmentation over a locally generated clip. It reports `model_name=synthetic-scene-colour-marker`, `model_version=synthetic_scene_v1` and the limitation `SYNTHETIC_SCENE_DETECTOR`. It is not a road-user classifier and its output is not evidence. |
| **YOLO adapter is unverified (BLOCKED)** | `ai_engine/detection/yolo.py` implements the adapter contract but `torch`/`ultralytics` are not installed, so `DETECTOR_BACKEND=yolo` fails with a clear configuration error instead of pretending to work. No accuracy, latency or mAP number exists for this project. |
| **Tracker** | The default `IouTracker` is IoU-based and deterministic; track ids are **job-local** and are not a persistent identity of a person or vehicle. The ByteTrack adapter requires an optional dependency and was not exercised. |
| **Event rules are heuristics, not validated detectors** | Near-miss (convergence + proximity), collision candidate (sustained box overlap), pedestrian conflict, rapid-motion proxy, wrong-way and signal-line crossing. Only the first two are computed from the demo clip's geometry; wrong-way and signal crossing report `status: unavailable` because no calibration/mapping exists. |
| **No physical speed, distance or TTC** | All motion quantities are image-plane pixels per second, normalised by object scale. There is no camera calibration record, so no metres/second, braking distance or time-to-collision is produced anywhere. |
| **No collision determination** | Bounding-box overlap is a *candidate* signal only. A `collision_candidate` is never written as an accident, and no record marks an event as a confirmed crash without human review. |
| **No person/plate identification** | No facial recognition, no ANPR, no re-identification across cameras, no enforcement output. |
| **LLM path not exercised** | `LLM_PROVIDER=none`: the deterministic investigation analyser is the default and the only path that has been run. The optional adapter validates a strict schema, but no live provider call was tested. |

## 2. Data

| Limitation | Detail |
| --- | --- |
| All seeded records are synthetic | Two organizations, 3 departments, 6 assets, 2 contractors, 2 contracts, 4 cameras, 8 historical accident records and 6 users are generated by `scripts/seed_database.py`, marked `is_demo=true` and labelled DEMO in the UI. They are not Bhubaneswar or any other real government data. |
| Accident records are a CSV fixture | `datasets/sample_accidents/demo_accidents.csv`; each row carries a source reference and a verification status. Import is additive and does not merge records into AI counts. |
| **No open Indian municipal CCTV corpus exists** | Dataset research (`docs/DATASETS.md`) found fixed-camera corpora (AI City Challenge 2020 Track 4, DoTA, the ACCIDENT benchmark) but no downloadable Indian city CCTV accident footage; IDD/IDD-CRS are ego-vehicle data and mostly gated. Real footage must come from the city. `scripts/prepare_dataset.py` validates and can ingest it, but the default detector is not trained on it. |
| **No external dataset is present (BLOCKED)** | The official AI City Track 4 (Drive interstitial), RDD2022 India (S3 403) and BDD100K (login/licence) sources could not be fetched automatically. `scripts/datasets/` is complete and proven on a synthetic fixture, but no real annotation has been parsed and no real metric computed. Manual steps: `docs/quality/DATASET_ACQUISITION_REPORT.md`. |
| **Road-damage detection is not implemented** | `scripts/datasets/validate_annotations.py` understands RDD2022 VOC labels and `evaluate_models.py` can score damage boxes, but there is no damage model, so the product makes no damage claim. |
| **Hotspots are not risk rates** | Clusters are DBSCAN over located records with a configurable radius/minimum. Without traffic-volume (exposure) data no rate can be computed; the method note and UI say so explicitly. |
| Coordinates may be absent | Assets without coordinates cannot be spatially matched; the investigation then reports `no_asset_match` / `requires_field_verification` rather than guessing an asset. |
| Demo records accumulate | Each `demo_smoke.py` run adds a video, job, incident, investigation and work order. Use `seed_database.py --reset-demo-data` to start clean. |

## 3. Integrations

| Limitation | Detail |
| --- | --- |
| **Real RTSP / live CCTV: BLOCKED** | The adapter is server-side and refuses to fabricate a connection; `LIVE_CCTV_ENABLED=false` and no allowlisted source is configured. No real camera was contacted (that needs authorization and credentials). Only the labelled SIMULATED LIVE mode works. |
| **Supabase: proven on a Supabase-shaped instance, not on a hosted project** | The full cut-over was executed against `docker-compose.supabase.yml` (Supabase role set, `extensions` schema, TLS-only, pgbouncer transaction pooler on 6543): empty→head migrations (idempotent), RLS isolation through the pooler, append-only audit, 12/12 external-worker smoke, and a SQL-only bootstrap/schema path loaded into a fresh database. Still unproven: Supavisor's exact behaviour, plan connection limits, network path and backups — these need the project's DSN. Locally proven passwords/certs are not used on a project. |
| **Supabase connection-string foot-guns** | Migrations must use the direct 5432 URL (the app now refuses 6543), runtime must use the pooler (6543) with `?sslmode=require`, and rotating the app-role password requires a pooler restart. All are enforced or documented; a wrong-port deployment still cannot be detected from inside this repo. |
| Object storage is MinIO-compatible S3 | Locally verified with `cgr.dev/chainguard/minio`. `minio/minio` and `minio/mc` were removed from Docker Hub in September 2026 and quay.io no longer allows anonymous pulls, so the maintained Chainguard build of the same server is used. Only S3/object-storage behaviour was verified; no cloud provider was used. |
| No email, SMS, payments or external notification | Notifications are in-app only; nothing is sent to citizens, departments or contractors. |
| Map tiles come from OpenStreetMap | The default tile URL is public OSM; swap `NEXT_PUBLIC_MAP_TILE_URL` for a self-hosted or licensed tile server before any real deployment. |

## 4. Platform and operations

| Limitation | Detail |
| --- | --- |
| Single-process rate limiter | `SlidingWindowLimiter` is in-memory: it resets on restart and does not coordinate across replicas. A distributed deployment must move login limiting to Redis. |
| WebSocket fan-out | The in-process hub serves clients attached to one API process; the optional Redis pub/sub bridge is implemented but only the single-process path was verified. |
| No horizontal-scale story | Job claiming uses `SELECT … FOR UPDATE SKIP LOCKED` with leases; that is correct for multiple workers, but only one worker and one API process were run here. |
| Background processing requires the worker | Without `polling_worker --loop` (or Celery) a job stays `queued`. This is by design — the API never processes video in a request — but it means the demo needs two processes. |
| Retention and deletion | No automatic retention policy, legal hold or evidence-deletion workflow is implemented. A real deployment needs one before storing real footage. |
| Backup / restore | Not implemented or rehearsed. `pg_dump` plus the object store bucket would be the starting point. |
| Dependency and container scanning | `ruff` and `pytest` were run; no SCA/container image scanner was executed, and no vulnerability scan report exists. |
| Accessibility | Semantic landmarks, labels, focus styles and `aria-current` are present, and `prefers-reduced-motion` is respected, but no assistive-technology audit or automated axe run was performed. |
| Browser coverage | Verified in the bundled Chromium for `/login`, `/command` (desktop and 390 px), `/admin` and a dynamic work-order page. The capture surface reports a fixed 657×1014 PNG, so the 1440/1366/768/390 matrix, the remaining pages and modal/dropdown states were not systematically reviewed. |
| No automated UI tests | No Playwright/Cypress suite exists; UI verification was interactive. axe/Lighthouse were not run, so no WCAG claim is made. |
| Container images | API image built and run; worker and web images are defined and were built/run as recorded in the changelog — the web image is not wired into a reverse proxy/TLS terminator. |

## 5. Legal and procedural

- The prototype does not determine liability, negligence, fault, penalties or enforcement action for
  any person, department, driver or contractor, and it must not be presented as doing so.
- Record matches (asset → department → contract → contractor) prove only that records exist and that
  a contract's date range covers the event date. They do not prove responsibility.
- Every consequential decision in the workflow is a human action recorded in the audit log.
- No real personal or sensitive data is stored; users are demo accounts.
